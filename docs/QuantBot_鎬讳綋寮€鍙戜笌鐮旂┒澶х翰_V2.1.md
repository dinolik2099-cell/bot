# 第一部分：V1.0 原始大纲

QuantBot 量化自动交易系统
总体开发与研究大纲 V1.0
一、项目最终目标
本金：10,000 USDT
目标资金：90,000 USDT
主要目标周期：200天
研究窗口：180 / 200 / 240天
杠杆：1×
目标市场：Binance
最终形态：自动量化交易机器人
最终系统不是寻找一个“神奇模型”，而是：
多个经过严格验证、具有互补性的交易模型 + 市场状态识别 + 组合管理 + 动态资金管理 + 强制风险控制 + 自动执行。
二、最高原则
1. 资金安全
2. 策略长期正期望
3. 控制最大回撤
4. 稳定增长
5. 提高资本增长速度
6. 90,000U目标
不能为了第6项破坏前面五项。9倍是目标，不是允许系统冒险的理由。
三、系统总体架构
Binance → 市场数据层 → 数据清洗/验证 → Feature/指标层 → Market Regime Engine
→ 多类交易模型 → Signal Engine → Portfolio Manager → Risk Engine → Position Sizing
→ Execution Engine → Backtest / Binance Live
四、数据层
建立可靠的 Binance 历史数据仓库。
数据：OHLCV、成交量、Trade Count、Taker Buy Volume；条件允许时加入 OI、Funding Rate、手续费和滑点模型。
市场：Spot 与 USDT-M Futures，最终根据回测决定正式市场。
周期：15M、1H、4H、1D。
原始数据保留 CSV/ZIP；标准研究数据使用 Parquet。
必须支持：自动下载、并发下载、Retry、断点续传、Manifest、数据版本、缺失检测、重复检测、OHLC异常检测、时间连续性检测、上市/下市处理。
五、交易池 Universe
第一阶段：BTC、ETH、BNB、SOL、XRP、DOGE。
随后扩大到高流动性 Binance USDT 交易对。
考虑成交量、流动性、点差、上市时间、数据完整性、极端波动。
六、候选交易模型
趋势类：Trend Following、Trend Pullback、Momentum。
突破类：Donchian Breakout、Volatility Breakout、Structure Breakout、Breakout + Retest。
震荡类：Mean Reversion、Range Reversal。
结构类：Support/Resistance、Higher High/Higher Low、Lower High/Lower Low。
不提前认定哪个最好，由数据筛选。
七、市场状态识别
识别强趋势上涨、强趋势下跌、弱趋势、震荡、高波动、异常市场。
根据 Regime 决定允许哪些模型工作以及模型权重。
八、Signal Engine
多个模型产生信号后不能直接下单。
综合趋势一致性、成交量、波动率、市场环境、BTC环境、个币强弱、流动性、盈亏比形成 Signal Score。
九、Portfolio Manager
解决同时出现多个机会时的选择和资金分配。
考虑信号强度、相关性、市场状态、当前持仓和总风险。
不是所有信号全部买入。
十、Risk Engine
最高权限模块，任何模型不能绕过。
控制单笔风险、总持仓风险、最大资金占用、单币暴露、同方向暴露、相关资产暴露、日亏损、周亏损、连续亏损、最大回撤。
具备 Circuit Breaker：正常 → 降低仓位 → 停止新仓 → Emergency Stop。
十一、Position Sizing
不固定每单投入。
根据账户资金、允许亏损金额、止损距离、最大仓位和组合风险计算最终仓位。
具体阈值由回测决定。
十二、Exit Engine
测试固定R（1.5R、2R、2.5R、3R、4R）、ATR/结构/均线跟踪止损、部分止盈+趋势跟踪等退出方式，由回测决定。
十三、交易成本
模拟 Maker/Taker Fee、Spread、Slippage、Funding Rate、延迟、极端行情滑点。
进行成本压力测试。
十四、回测引擎
必须做到：无未来函数、正确K线时间、正确订单执行顺序、正确止损/止盈、手续费、滑点、仓位和复利、同时持仓。
十五、并行研究
利用服务器 36 物理核心 / 72 逻辑核心 / 64GB RAM。
研究维度：模型 × 币种 × 周期 × 参数 × 市场阶段 × 风险参数。
采用多进程和任务队列，避免无意义的暴力参数搜索。
十六、模型筛选
核心指标：Total Return、CAGR、Max Drawdown、Profit Factor、Sharpe、Sortino、Win Rate、Average R、Expectancy、最大连续亏损、Recovery Factor、Calmar、Turnover、Cost Sensitivity。
不能按收益最高单一指标选择。
十七、模型组合
研究模型之间的相关性。
最终可能使用一个模型，也可能使用多个互补模型。
目标：降低资金曲线相关性，提高风险调整后收益。
十八、Walk-Forward
必须进行训练、验证、样本外测试和滚动重新训练。
禁止使用全部历史数据调参后直接宣布成功。
十九、Rolling 180/200/240天测试
每个历史窗口从10,000U重新开始。
测试180、200、240天，统计达到90,000U的比例，同时统计最大回撤等风险指标。
二十、Monte Carlo
对历史交易结果进行大量重采样，测试最大回撤、连续亏损、最低资金、达标概率和 Risk of Ruin。
二十一、压力测试
人为增加手续费、滑点、延迟，并模拟连续亏损、极端行情、BTC暴跌、山寨币集体暴跌和流动性下降。
轻微恶化即失效的策略淘汰。
二十二、最终评分
寻找“安全约束下的最高资本增长效率”。
重点：风险调整收益、稳定性、样本外表现、回撤、目标达成概率。
二十三、Paper Trading
历史测试通过后先实时模拟交易，验证行情、信号、仓位、止损、延迟、API、日志和异常恢复。
二十四、Binance API
最终接入 API Key。
允许交易，禁止提现，最好设置 IP 白名单。
二十五、Live Safety
必须具备 Kill Switch、API异常保护、网络异常保护、数据异常保护、重复下单保护、订单状态恢复、程序重启恢复、持仓同步和账户风险检查。
二十六、正式资金部署
Paper → 极小资金 → 小资金 → 逐步增加 → 正式资金。
每一步都有暂停条件。
二十七、最终运行模式
获取行情 → 检查数据 → 判断市场状态 → 运行候选模型 → 筛选信号 → 组合排序 → 风险检查 → 计算仓位 → 执行 → 设置保护订单 → 监控 → 记录。
没有机会时不交易。
二十八、最终目标评价
系统最终必须回答：
1. 能不能赚钱？
2. 能不能持续赚钱？
3. 最大会亏多少？
4. 极端情况下能不能活下来？
5. 在安全约束下，10,000U → 90,000U需要多久？
二十九、开发阶段
PHASE 0 环境与项目规范
PHASE 1 数据仓库

PHASE 3 候选模型池

PHASE 12 Paper Trading

三十、项目纪律
不能为了漂亮的回测结果而修改研究方法。
不能只挑收益最高的参数。
必须验证样本外、跨币种、跨市场环境、成本敏感性和最大回撤。
目标是找到真正能长期运行的系统，而不是历史神策略。
最终定义：
QuantBot 是一个以资本保护为最高优先级、通过多个经过严格验证的交易模型寻找机会、根据市场状态动态选择模型、根据组合风险动态分配资金、能够自动交易并在异常情况下自动刹车的完整量化交易系统。
10,000U → 90,000U / 200天是衡量系统能力的目标，不是让系统为了达标而冒险的理由。

# 一、总体定位

QuantBot 不是“寻找一个神奇策略”的程序，而是一个以资本保护为最高优先级的研究、验证、组合和自动交易系统。

核心闭环：

```text
市场数据
  ↓
数据质量与研究边界
  ↓
特征 / 指标层
  ↓
市场状态识别
  ↓
多模型候选池
  ↓
信号生成
  ↓
信号过滤 / 模型监督
  ↓
组合管理
  ↓
风险管理
  ↓
仓位计算
  ↓
执行
  ↓
交易记录与失败交易分析
  ↓
研究反馈
  ↓
模型更新
```

最终形成：

```text
数据 → 模型 → 验证 → 组合 → 风险 → 执行 → 反馈 → 再研究
```

# 二、ABU 对 QuantBot 的借鉴原则

ABU 的价值不是让 QuantBot 直接复制 ABU，而是借鉴其“基础策略 + 优化监督 + 多模型组合 + 失败交易分析”的研究思想。

ABU 官方项目明确提出：
- 分离基础策略与策略优化监督模块；
- 支持 K 线形态、趋势线、突破、均线、波浪、缠论、谐波、经典指标、时间序列、统计概率等多类分析；
- 支持止盈止损、风险控制、滑点和手续费研究；
- 支持多资产回测与仓位管理；
- 包含机器学习优化、失败交易分析以及 UMP 主裁思路。

QuantBot 只吸收这些经过工程化验证的思想，不直接复制 ABU 的旧架构。

重要原则：

```text
ABU 中“存在的模型”
        ≠
QuantBot 中“已经有效的模型”
```

所有外部模型进入 QuantBot 后必须重新经过：

```text
TRAIN → VALIDATION → 冻结 → OOS
```

不得因为 ABU 已经实现就直接认定有效。

# 六、第四层：市场状态识别

这是原大纲中的核心模块，也是后续重点。

目标不是预测下一根 K 线涨跌，而是回答：

> 当前属于什么市场环境？

初步状态：

```text
强趋势上涨
强趋势下跌
弱趋势
震荡
高波动
低波动
突破阶段
趋势转换
异常市场
```

市场状态决定：
- 哪些模型允许工作；
- 模型权重；
- 最大风险；
- 是否允许开新仓。

# 十、第七层：交易监督 / 失败交易分析

这是本次借鉴 ABU 后新增的重要架构层。

目标：

> 找出“策略为什么失败”，而不是只看最终收益。

每笔交易记录：

```text
入场时间
出场时间
方向
入场价格
止损
止盈
持仓时间
收益
R倍数
市场状态
波动率
趋势强度
成交量
信号来源
```

之后分析：

```text
盈利交易特征
        vs
亏损交易特征
```

以后可以进一步建立“交易监督器”，过滤高概率失败交易。

这借鉴 ABU 的失败交易 / UMP 主裁思想，但 QuantBot 会采用自己的严格 OOS 训练方式。

# 十八、最高原则不变

1. 资金安全第一。
2. 不为了目标收益破坏风险约束。
3. 不因为 ABU 有某个模型就认为该模型有效。
4. 不因为历史回测好就认为未来有效。
5. OOS 不参与模型选择。
6. 所有模型必须经过统一验证。
7. 所有模型必须经过成本和回撤检查。
8. 复杂模型不享有特殊待遇。
9. 能被简单模型解释时，不优先使用复杂模型。
10. 最终目标是找到能够长期运行的系统，而不是历史上最漂亮的曲线。
