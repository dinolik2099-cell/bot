# QuantBot Phase 2.4-B 最坏情况压力测试 V1.1

## 目的
本版不是为了寻找最高收益，而是继续回答：

1. 最坏情况下还能不能活下来？
2. 正常情况下是否仍有稳定正期望？
3. 最好收益本阶段不作为筛选依据。

## V1.0 已发现的问题
V1.0 的“交易顺序随机重排”中，最终资金使用固定交易收益样本复利，因此无论顺序如何，最终资金理论上相同；它只能用于观察路径最大回撤/最低资金，不能把最终资金分位数当作有效随机结果。

V1.1 已修正，并增加真正会改变最终资金分布的 Bootstrap。

## 新增测试
- 10 个手续费/滑点压力场景 × 3 个组合 × TRAIN/VALIDATION = 60 次共享资金回测。
- 交易顺序重排：观察路径最大回撤、最低资金、连续亏损。
- 交易 Bootstrap：有放回抽样，观察最终资金与尾部回撤。
- 7 日 Block Bootstrap：基于实际 VALIDATION 每日组合权益变化，保留短期收益簇结构。
- 收益削弱 30%：模拟执行恶化，不修改策略参数。
- 极端不利排序：人为把亏损集中到前段，只用于观察极端生存边界，不解释为现实概率。
- 共享资金执行审计：交易字段、NaN/Inf、单币持仓重叠等。
- 修复 pandas/numpy 整数索引兼容问题，避免 SL/TP 检查因 `numpy.int64` 被错误跳过。

## 数据纪律
- 只允许 TRAIN / VALIDATION。
- 不读取 OOS。
- 不读取 D-2 / D-3 结果参与计算。
- 不修改 D-1 冻结参数。
- 不用于反向调参。

## 运行
在 `/www/wwwroot/QuantBot`：

```bash
source venv/bin/activate
python scripts/test_phase2_4_b_worst_case_stress_v11.py
python scripts/run_phase2_4_b_worst_case_stress_v11.py --workers 6 --mc 20000
```

如果服务器 CPU 充足，可以先保持 `--workers 6`，因为主要共享资金回测目前是确定性顺序执行；不要为了“占满 CPU”盲目增加进程。

## 重点把结果发回来
优先看：
- 高成本压力下 Validation 的最大回撤、盈利因子、最终资金；
- 交易 Bootstrap 的最差 1% / 0.5% / 0.1% 最大回撤；
- 交易 Bootstrap 的最低资金分位数；
- 7 日 Block Bootstrap 的最差尾部；
- 收益削弱 30% 后的尾部；
- 极端不利排序的最大回撤和最低资金；
- 执行审计是否全部通过。

本阶段仍然不进入 OOS，也不进入退出模式优化。
